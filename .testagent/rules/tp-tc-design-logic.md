# TP/TC 设计逻辑规则

> 本文件定义：一个 TS 如何展开为 TP、一个 TP 如何展开为 TC，以及 TP 的 tpType / tpSourceType 取值。test-design skill 引用本文件执行展开；业务调整展开方法或参数取值时只改本文件。

## 一、TS → TP：4 维度展开

对单个 TS，从以下 4 个维度分别提取 TP，汇总为该 TS 的完整 TP 列表：

| 维度 | 名称 | 提取角度 |
|------|------|---------|
| 维度1 | 基于业务场景 | 从业务用例、关键路径、场景触发条件组合提取 |
| 维度2 | 基于业务内部实现 | 从模块交互、核心处理逻辑、异常分支提取 |
| 维度3 | 功能交互设计 | 从功能节点交互、接口调用关系、数据流提取 |
| 维度4 | 测试类型交互设计 | 从边界值、错误推测、经验库匹配提取 |

每个维度提取出的每个 TP，需带：TP 名称、TP 描述、Level(0-4)、关联测试因子(TFA/TFD)、所属维度。

## 二、TP 的 tpType / tpSourceType 取值

每个 TP 按其所属维度，填下表对应值（不得自行编造其他值）：

| 维度 | tpType | tpSourceType |
|------|--------|--------------|
| 维度1 基于业务场景 | `BusinessSceneAnalysis` | (留空) |
| 维度2 基于业务内部实现 | `SceneAnalysis` | (留空) |
| 维度3 功能交互设计 | `RequirementAnalysis` | `功能交互设计-功能上测试因子` |
| 维度4 测试类型交互设计 | `RequirementAnalysis` | `测试类型交互设计-测试因子` |

**合法取值集合**（人工修改取值时，只能在此范围内）：
- tpType ∈ { `BusinessSceneAnalysis`, `SceneAnalysis`, `RequirementAnalysis` }
- tpSourceType ∈ { `功能交互设计-功能上测试因子`, `测试类型交互设计-测试因子`, 空 }

## 三、TP → TC：覆盖展开

**强制要求：每个 TP 必须至少有 1 个对应 TC，TP→TC 覆盖率 100%。**

- 每个 TP 根据其测试因子组合、边界条件，展开为 1 个或多个 TC
- 不允许只为高优先级 TP 生成 TC、跳过低优先级(Level3/4)
- 每个 TC 需带：用例名称、Level、预置条件、测试步骤、预期结果、用例编号
