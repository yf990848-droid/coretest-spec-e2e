# coretest-spec-e2e 0.2.8 指导教程

适用版本：coretest-spec-e2e 0.2.8。本版本优化了测试用例卡片更新流程。

## 1. 使用前准备

1. 在 TestAgent 中加载 coretest-spec-e2e 0.2.8 扩展包。
2. 安装 Python 3.11 或以上版本，推荐 Python 3.12；Windows 安装时建议勾选 Python Launcher 和 Add python.exe to PATH。
3. 确认当前账号具有对应产品版本、测试设计任务和全量测试设计平台的访问权限。
4. 完成 CoreTool CLI 登录。

**MCP 服务由工具自动启动，无需手动运行启动脚本，也无需单独保持终端窗口。**首次使用时请确保能访问公司内网依赖镜像。

在扩展包根目录打开 PowerShell，执行登录命令：

```powershell
.\.testagent\skills\coretool-cli\tools\coretool-cli.exe auth login
```

按提示完成登录后，可检查登录状态：

```powershell
.\.testagent\skills\coretool-cli\tools\coretool-cli.exe auth status
```

详细登录说明见 CORETOOL_CLI_LOGIN.md。

## 2. 操作流程

按以下顺序操作：

1. 初始化产品版本。
2. 在平台确认或创建 TR（测试需求）。
3. 生成 TS（测试规格）。
4. 生成 TP（测试点）和 TC（测试用例），检查用例卡片。
5. 将确认后的结果归档到平台。

以下命令在 **TestAgent 对话框** 中输入。示例中的产品版本、TR ID 和 TS 编号请替换为实际值。TR ID 是平台上的测试需求 ID，不是设计任务 ID。

## 3. 初始化：选择产品版本和 TR

输入：

```text
/coretest-init "UPCF 27.0.0"
```

等待工具展示全量测试设计平台卡片，按提示选择目标设计任务和 TR。

如果尚未创建 TR，请在右侧卡片中创建，并关联对应需求及需要的特性或功能。完成后在对话框输入：

```text
TR已创建
```

工具会重新获取 TR 信息。确认目标 TR 后进入下一步。

## 4. Explore：生成测试规格

### 4.1 发起分析

可以在全量测试设计卡片的 TR 节点右键点击【AI分析】，也可以输入：

```text
/coretest-explore 4029
```

等待分析结束，检查生成的测试规格是否覆盖本次需求。

### 4.2 选择是否归档 TS

工具会询问是否归档本轮生成的普通 TS：

- 选择“直接归档全部普通 TS”：将测试规格写入平台，方便后续从卡片触发测试设计。
- 选择跳过：暂不归档，后续仍可通过命令继续测试设计。

平台已有的 DFX TS 会被复用，无需重复创建。

## 5. Design：生成测试点和用例

### 5.1 从卡片发起

- 单个 TS：在 TS 节点右键点击【AI分析】。
- 多个 TS：在 TR 节点进入【关联对象 → 关联的 TS】，多选目标 TS 后点击【AI分析】。

### 5.2 通过命令发起

处理指定 TS：

```text
/coretest-design 4029 TS_18
```

处理多个 TS：

```text
/coretest-design 4029 TS_11 TS_12
```

处理当前 TR 下全部 TS：

```text
/coretest-design 4029
```

已具备真实平台 TS ID 时，也可按该 ID 指定，例如：

```text
/coretest-design TR_4029 TS_40152
```

### 5.3 检查结果

等待生成结束后，检查：

- 对应 TS 的用例卡片已显示，并更新为完成状态。
- 测试点和用例属于所选 TS，没有遗漏或相互覆盖。
- 用例名称、前置条件、操作步骤及预期结果符合需求。
- 如需调整，在对话中说明具体 TS、用例及修改要求，再检查更新后的结果。

**卡片由工具自动更新，用户无需手动运行卡片脚本。**不要仅凭对话中的“调用成功”判断完成，还需确认页面上的卡片内容已刷新。

Design 会同时准备相关测试因子信息；平台上的实际关联在归档时完成。

## 6. Archive：归档到平台

检查设计结果后，按需要选择归档范围。

| 目标 | 示例命令 |
|---|---|
| 复用 TR 并同步相关文档 | `/coretest-archive 4029 TR` |
| 归档全部 TS | `/coretest-archive 4029 TS` |
| 归档指定 TS | `/coretest-archive 4029 TS_18` |
| 归档全部 TP 及所属 TS | `/coretest-archive 4029 TP` |
| 归档指定 TP 及所属 TS | `/coretest-archive 4029 TS_18/TP.18.01` |
| 归档全部 TC 及所属 TS、TP | `/coretest-archive 4029 TC` |

指定 TP 时，请使用本次实际生成的编号。归档指定 TS 或 TP 不会自动包含其下全部用例；需要归档用例时应选择相应的 TC 范围。

归档结束后：

1. 查看工具汇总，确认是否有失败或部分成功的项目。
2. 在右侧全量测试设计卡片检查归档对象。
3. 查看相关在线文档和因子关联是否符合预期。

## 7. 查看本地结果

当前 TR 的结果统一保存在：

```text
.design_output/<设计任务ID>/TR_<TR ID>/
```

常用位置：

| 内容 | 位置 |
|---|---|
| 测试规格 | test_specs 目录 |
| 测试设计和用例文档 | test_design 目录 |
| 归档记录 | archive 目录 |

通常通过卡片和工具汇总即可查看结果，不需要手动修改这些文件。

## 8. 常见问题

### 提示 CoreTool 未登录

按第 1 节重新登录，再执行原命令。

### MCP 自动启动失败

确认已安装所需 Python 版本，并检查内网连接。仍无法使用时，将工具显示的错误信息提供给维护人员排查，无需自行反复启动 MCP。

### 卡片没有显示，或仍是旧内容

先确认已加载 0.2.8 扩展包并等待当前任务完成。仍未刷新时，将 TR ID、TS 编号和工具错误信息提供给维护人员；不要反复手动运行卡片脚本。

### 没有匹配到测试因子，是否代表失败？

不一定。查询成功但没有匹配因子时，可以继续；如果工具明确报告查询失败，需要先处理该错误。

### 归档中断后如何继续？

修复提示的问题后，使用相同 TR 和归档目标重新执行，例如：

```text
/coretest-archive 4029 TS_18/TP.18.01
```

保留原有结果和归档记录，不要删除 archive 目录。工具会复用已成功的对象，继续处理未完成部分。
